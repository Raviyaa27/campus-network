Dual-homing is intentional. Each distribution switch and SW-A-DIS has two uplinks — one to each core. This creates a Layer 2 loop by design; spanning tree blocks the redundant path and reactivates it automatically on failure. STP root priority is aligned with the HSRP active role so the unblocked path always leads to the active gateway.

What to expect once cabling is complete

Normal at this stage

  • GNS3 may warn about a Layer 2 loop after batch C — this is by design, ignore it.
  • Every interface shows down/down. Nothing has been configured yet.
  • Switches boot to Switch>, routers to Router>.
  • Nothing pings. No addressing has been applied to any device.
  • IOSvL2 takes 2–4 minutes to boot. Wait for the prompt before assuming a fault.

Verify before configuring

  • Start only R-EDGE, R-CORE, SW-CORE-1, SW-CORE-2 (~2.6 GB).
  • Each reaches a CLI prompt.
  • show ip interface brief lists Gi0/0–Gi0/3 on routers.
  • show ip interface brief lists Gi0/0–Gi3/3 on switches.
  • Save the project, then take a GNS3 snapshot named 00-cabled-baseline.
Take that snapshot. It is the clean state to roll back to whenever a later configuration step goes wrong, and the MOP requires a documented rollback point before each major change.

Why alternate the active role? Leaving one core as a cold standby wastes half the core capacity. Splitting the VLANs means both switches forward traffic in normal operation, and either one can carry everything after a failure. The standby keeps the default priority 100, and preempt is enabled on both so the intended active switch reclaims its role once it recovers.
Why STP root must match HSRP active. If SW-CORE-1 is the gateway for VLAN 10 but SW-CORE-2 is the STP root for it, every VLAN 10 packet reaches CORE-2 at Layer 2, crosses the peer link to find its gateway on CORE-1, and comes back — turning Po1 into a bottleneck for no reason. Aligning the two keeps the forwarding path direct.

Then, and only then

Move on to device configuration: hostnames, VLAN database, trunk links with native VLAN 100, the core SVIs, HSRP, and management access on VLAN 99. Configure and verify the core pair before starting any distribution or access switch — a fault in the core is far easier to find with four devices running than with eleven.
